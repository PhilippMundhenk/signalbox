## [Unreleased]

### Added
- Device HTTPS certificates (ADR 0019): `Device.certificate` (issuer, validity, key type and size, signature, SANs, covers the management address, trusted since) read by core from the pinning handshake of every HTTPS adapter, a *Certificate* card on the device page, checks `security.certificate-expiry` (warning 30 days, error 7 days and after expiry; `certificates.warn_days`/`urgent_days`), `cert.weak-key` and `cert.renewed` (explains an untrusted status after a regenerated certificate); certificates stored on devices (VPN, RADIUS, CA) are #330; behaviour on real devices unconfirmed (#174, #121, #21)
- Topology: devices without cables sit in a labelled "Not cabled" strip at the bottom of their site, VPN arcs run above the site titles, site frames hug their content and Fit enlarges small drawings up to 1.8x (#328)
- Larger demo network: two sites with 12 devices (OPNsense and Linux gateways joined by WireGuard, OpenWrt router, APs and switch with VLAN trunks, Omada, NETGEAR and TP-Link switches, AdGuard Home, Pi-hole, a bundle of two cables, one partly read router) and refreshed screenshots; `demo_devices(compact=True)` keeps the small network for tests (#324)
- MikroTik firewall writer: rules, port forwards (`dst-nat`) and zone policies (interface lists) as rows tagged `signalbox:<key>` (only tagged rows changed or removed, the device's own with `adopt`), protected by a `/system/scheduler` revert timer (RouterOS safe mode is not available over REST) that `confirm` removes; backup and restore cover the firewall menus; confirmed in CI on the CHR, other versions and real routers unconfirmed (#295, #21)
- Log and monitoring targets (ADR 0018): `Device.log_targets` (syslog, NetFlow/IPFIX, SNMP traps, collectd metrics) read from OpenWrt (logd, optional snmpd, luci_statistics, softflowd; three configs join the read ACL), MikroTik (remote logging actions, traffic-flow, SNMP trap targets), OPNsense (syslog destinations, NetFlow; two new read privileges) and Linux (rsyslog, syslog-ng); the OpenWrt snmpd agent feeds the default-community check; checks `log.target-unknown` and `log.inconsistent`; a *Logging and monitoring* card on the device page; confirmed in CI on OpenWrt, OPNsense and the CHR defaults, package layouts and configured routers unconfirmed (#180, #21)
- AdGuard Home and Pi-hole: Pi-hole clients (network table), the DNS server DHCP hands out (both hand out themselves unless Pi-hole's `dnsmasq_lines` say otherwise), and discovery probes for both (`/control/status`, `/api/info/login`); AdGuard IP-only clients stay unlisted (the model keys clients by MAC); unconfirmed on real devices (#314, #21)
- Automatic setup shows the step that is running: apply runs as a background job (`POST /api/devices/setup/jobs`, polled `GET .../jobs/{id}`) and the UI lists each step as waiting, running now, done or failed with its message; the admin password is only in the start request, never in the job (#316)
- Translations: the findings of all rules (except the firewall rules) and the HTTPS/SSH transport errors carry message ids with German texts; English wording of some findings changed (comma lists, short time units, arrows for links) (#204)
- Translations: Spanish (`es`, tú), French (`fr`, vous) and Brazilian Portuguese (`pt`, você); every catalogue in `index.json` is tested for complete keys and equal placeholders, and each language has a browser smoke test (#204)
- AdGuard Home and Pi-hole v6 as read-only devices (role other): DNS service and port, upstream servers as forwarders, DHCP server with leases and reservations, local DNS records, configured clients (AdGuard Home); Pi-hole v5 is reported with a fix; simulator-tested, not yet confirmed on real devices (#304, #241)
- Firewall desired state and deployments (ADR 0017): `firewalls` per device with zone policies, rules and port forwards (zone names or segments), `drift.firewall` and import; change kinds `zone-policy`, `firewall-rule`, `port-forward`; OpenWrt writes only tagged `sb_*` UCI sections (the device's own objects only when adopted; `firewall` joins the write ACL and backups); a plan that may cut Signalbox off from a device (reachability before and after, `deploy.signalbox_address`) needs the explicit *Allow losing management access* override; confirmed in CI on OpenWrt 24.10 and 25.12; OPNsense and MikroTik later (#295)
- OPNsense applies firewall rules, port forwards and zone policies (tagged `signalbox:<key>` in the description; the device's own rules only with `adopt`); OPNsense 26.7 has no rollback timer, so the lockout check and the backup restore are the protection (#295)
- MAC table checks: `mac.flapping` (a MAC moving between access ports, from the history), `mac.static-stale`, `mac.table-full`; `clients.network-changed`, `vlan.client-port-mismatch` and `inventory.unknown-neighbour` use the learned VLAN, port and own addresses from the tables (#298, #160, #85, #112, #113)

### Changed
- Notices and errors: every page, form and dialog has one notice place; a newer result replaces it, a success or new attempt clears it, page errors can be dismissed, and errors are no longer toasts (#311)
- Topology diagram redesigned: layers by role and uplink direction with fewer crossings, parallel cables bundled with a count badge, sites as groups, wires end at the port squares, collapsible legend, device names link to their page, hover highlight, zoom/pan/pinch and a full-screen view (#303)
- Setup preview: a test per integration (Linux, OpenWrt, MikroTik, OPNsense with its ISC SSH script, every *Fix it* remedy) checks that the credential-free preview lists every step the real plan can contain (fixing three missing ones); OPNsense with the optional SSH step now fetches the HTTPS certificate and the SSH host key together before any password, so the passwords are asked once (#290)
- VLAN 1 counts as the native (untagged) network, so devices that report their LAN as VLAN 1 and devices that report it untagged agree; a VLAN tagged on only one end of a link is a warning (#17)
- Both adapters use one HTTPS helper that pins the device certificate in the TLS connection itself; the plain-HTTP setting is `allow_insecure_http` for every adapter (#34)
- Each device links to its own web interface: an icon on the devices list and an "Open web interface" button on the device page, derived from a reported https/http service or the adapter settings (#214)

- Docker base image is now `python:3.15-slim` (was 3.13); the unit tests also run on Python 3.15 in CI (#270)
### Fixed
- Flaky e2e tests: the traces test waits for the finished run, and the live test server keeps its bound port (#321)
- Automatic setup UI: Enter never saves the device form (Enter runs the setup), connection fields come before the setup box, a spinner progress state, an admin login in the settings is replaced by the login Signalbox creates, and a refused admin login returns to the password step keeping the preview and identity (#299)

- OpenWrt without Wi-Fi (a switch): no wireless object means no radios, not a read error (#216)
- Navigation: the top bar no longer wraps on phones and tablets; side bar on wide screens, menu drawer on narrow ones (#230)
- Finding devices lists a device that answers on several addresses once (same certificate, MAC, serial number or controller id), with all its addresses and the one in a known network offered, and marks it as added when any of its addresses or its identity belongs to a device you already added (#224).
- NETGEAR ProSAFE Plus: an old switch that refuses the full identity read (answering "incorrect password" even without one) is read from its discovery answer; a refused setting is named in the error (#210)
- NETGEAR ProSAFE Plus switches are read without logging in, as Switchyard does; the password is optional and only checked for changes (an old GS108E v1 refused the check while reading worked) (#210)

- OPNsense: Kea fills NTP servers (like routers and DNS) with the interface address on every save; an empty value is read that way now (#179)
- Fritz!Box: the user name may stay empty (boxes without users); a cleared form field is no longer refilled with its default (#202)
- NETGEAR ProSAFE Plus: the switch's identity is read before the login, as Switchyard does, so old firmware gets its password scheme (#202)
