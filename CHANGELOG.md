## [Unreleased]

### Added
- Multicast (#161, PR #506): `Device.multicast` holds IGMP/MLD snooping and querier per bridge (or VLAN) and the reflectors (mDNS, SSDP, UDP broadcast relay, IGMP proxy) with the networks they join; MikroTik reads the bridge settings, `mdns-repeat-ifaces` (7.16+) and `/routing/igmp-proxy/interface`, OpenWrt the kernel's bridge values (sysfs, UCI as fallback), `igmpproxy` and the Avahi reflector (two new read-ACL entries, an older ACL is an optional gap), OPNsense `os-mdns-repeater` and `os-udpbroadcastrelay`, UniFi the `igmp_*` and `mdns_enabled` network fields; new rules `multicast.snooping-no-querier`, `multicast.reflector-guest`, `multicast.reflector-missing` (`min_clients`) and `multicast.iptv-proxy`; Omada, SNMP, the OPNsense IGMP proxy page (no API), a UI card and writes stay open, and the plugin, option and field names are guesses (#21)
- Zone-based firewalls and lldpd leftovers (#504, #494, PR #505): the edgeos adapter reads `zone-policy zone` (EdgeOS 1.10/2.x, VyOS 1.3) and `firewall zone` (VyOS 1.4/1.5) into the zone and policy model (zones with their member interfaces, the rules of `from` rule-sets per zone pair in the forward chain, input for the local zone and output from it, rule-set default actions, the target zone's default action as policy for pairs without a rule-set, intra-zone filtering) and the "not read" finding is gone; the VyOS CI lab has a zone policy and asserts it; `zone-policy` of EdgeOS and VyOS 1.3 follows the documented syntax only (#21); lldpd stores a CDP native VLAN as `pvid`, so `port_vlan` is filled for CDP, while lldpd decodes no VTP domain or duplex and its age is the time since the last change, so `last_seen` stays empty for lldpd (documented, nothing left to read)
- PoE reserved power and the changing user (#484, #482, PR #497): the SNMP and UniFi readers fill `PoeSupply.reserved_w` (neither POWER-ETHERNET-MIB nor UniFi reports an allocation, so it is the 802.3 class maximum of every delivering port with a class), so `poe.budget-margin` can fire; `config.changed-outside` names the user the device logged for the change; reserved power for MikroTik, OpenWrt and Omada and PoE writes stay open
- Dynamic DNS readers (#450, PR #496): Linux reads ddclient 3.9-3.11 and inadyn 2.x (`/etc/ddclient.conf`, `/etc/inadyn.conf`, their cache files) into `DynamicDns` (provider, host name, family, tls, last update, last result, announced address); the account, password and token lines are removed on the device and again by the reader (allow-list of keys), and the sudoers rule gains `cat` of exactly those two files (repair it through Set up automatically / Repair access); optional `ddns.resolve` (off by default, sends a DNS query per name from Signalbox's host) feeds `ddns.mismatch`; Omada has no dynamic DNS read and is documented as not available; inadyn 2.x cache names and HTTPS default and the ddclient 3.11 cache path are guesses (#21)
- CAPsMAN follow-ups (#481, PR #493): the radios and SSIDs of each managed CAP are `Radio`/`Wlan` of the CAP device (`/caps-man/interface`, or the CAP-assigned `/interface/wifi` rows on RouterOS 7), clients in the controller registration tables (`wifi`, `wireless`, `/caps-man`) are attributed to the CAP interface, and the CAP uplink is read (segment, layer 2 or 3 path, controller port, `mesh.uplink` wired or wireless); the `remote-cap-*` radio columns and the dotted `/caps-man/interface` REST columns are guesses (#21)
- VyOS 1.4/1.5 follow-ups (#495, PR #498): optional automatic setup for the edgeos adapter (admin login over SSH, only on explicit start) that reads the version before it builds the plan: EdgeOS and VyOS up to 1.3 get `level operator`, VyOS 1.4 and newer (no user levels; the `level` option is probed on the router) a key-only user without a level and a plan step that says it has full rights, with how to narrow it down in docs/adapters/edgeos.md; `firewall ipv4`/`ipv6` forward, input and output filters, interface matches and named chains (jumps unrolled) are read into the firewall model, `firewall name` of EdgeOS and VyOS 1.3 unchanged; the VyOS CI job has a lab firewall, asserts it and runs the automatic setup, and shows a job-summary warning with the tag and SHA-256 to re-pin when the pinned rolling build is gone; the `show` read as a full-rights user on VyOS 1.4+, the 1.4.0 early `interface-name` spelling and `options` for restricting a key are guesses (#21)
- VyOS integration job (#432, PR #488): the edgeos adapter runs over SSH against the official VyOS rolling ISO (2026.11.25, pinned by SHA-256) booted headless in QEMU: read user, ports, VLAN, subnets, DHCP, DNS forwarding, NAT, routes, health and time, host key pin; rolling has no `level operator` (user levels were dropped) and its `firewall ipv4/ipv6` rule-sets are still not read (gap, status partial); VyOS 1.3/1.4 and EdgeOS stay simulator-only (stable images are subscriber-only)
- LLDP leftovers (#470, PR #492): OPNsense neighbours from the `os-lldpd` plugin (`/api/lldpd/service/neighbor`, the text of `lldpcli show neighbors`: chassis and port ids, system data, capabilities, VLANs, MFS, TTL, age; privilege `page-services-lldpd`, set up only where the firewall offers it; 404 none, 403 an optional gap); UniFi `lldp_table` entries add protocol, chassis id kind, port description and capabilities to the uplink neighbour; Omada has no LLDP neighbour read and is documented as not available; the lldpcli text layout and the UniFi capability field name are guesses (#21); `last_seen` stays empty for lldpd (its age counts from the first sighting); CDP-only data (VTP, duplex) stays open
- Wi-Fi readers and MQTT opt-in (#469): Omada 802.11k/v, band steering, airtime fairness, DTIM and minimum RSSI (guessed spellings), MikroTik FT key holder and client 11r/WPA3 capabilities; `exports.wifi_clients` (off by default) publishes each client's SSID, band and signal per access point over MQTT, MAC addresses only with `exports.identity` too.
- UniFi integration job (#432, PR #483): the UniFi adapter runs against the real Network application 8.6.9, 9.5.21 and 10.6.109 (Docker with MongoDB, no adopted device; first-run administrator and read-only account created through the controller API; login, site, networks, DHCP, health, auth failures); VyOS in QEMU for the edgeos adapter stays open
- Port counter history series (#471, PR #477): the store (schema 9) keeps hourly traffic buckets per port for `history.days`; `port.utilisation` judges a percentile (`percentile`, `window_hours`, `min_coverage_pct`) of the hourly rates and `port.idle-trunk` a sustained idle period (`idle_hours`), both falling back to the last read interval while the series is short; `GET /api/devices/{id}/port-series` and a per-port traffic sparkline on the device page.
- PoE follow-ups (#468, PR #478): `powered_by` on devices and `powers` on ports in the network API, "Powered by <switch> port <n>" on the device page and the reverse on the switch's PoE card and port list; checks `poe.budget-margin` (reserved power against the budget, `reserved_pct`) and `poe.passive-on-standard` (UniFi passive mode on a port whose device announces standard PoE).

- OpenWrt without Wi-Fi (a switch): no wireless object means no radios, not a read error (#216)
- Navigation: the top bar no longer wraps on phones and tablets; side bar on wide screens, menu drawer on narrow ones (#230)
